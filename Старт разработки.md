# Старт разработки: от чернового макета к игровому экрану

Текущий `prototype/first-screen` — схема расположения объектов и проверка кликов. Сцена в `game/` — исследование камеры, планировки и объёма. Игровые правила и интерес цикла ещё не проверены. Следующий шаг работы — [геймдизайн и системный дизайн](Геймдизайн и системный дизайн.md); художественную доводку продолжаем после серого игрового прототипа.

## 0. Согласовать игровой цикл и системы

1. Записать короткий GDD первого дня после катастрофы: цель, решения, время, ресурсы, последствия и ошибки.
2. Описать связанные системы по единому шаблону: состояние, команды, проверки, события и сохранение.
3. Проиграть в таблице две последовательности действий и устранить ресурсные тупики.

Готовность этапа: первый цикл можно объяснить и просчитать по документам; перечень механик малого прототипа закрыт. Этот этап сейчас в работе.

## 1. Установить инструменты

**Проверено 6 октября 2026:** .NET SDK `10.0.401` и Godot `.NET 4.7.2` найдены на рабочем компьютере. В терминале, открытом до установки .NET, команда `dotnet` может появиться после открытия нового окна; проверка по прямому пути прошла.

1. Скачать **.NET 10 SDK x64** с [официальной страницы Microsoft](https://dotnet.microsoft.com/en-us/download). Нужен именно SDK, не только Runtime. Запустить установщик.
2. Закрыть и снова открыть PowerShell. Выполнить `dotnet --list-sdks`. В списке должна быть версия `10.0.x`.
3. Скачать **Godot Engine 4.7.2 — .NET — x86_64** с [официальной страницы Godot для Windows](https://godotengine.org/download/windows/). Выбрать вариант с пометкой `.NET` и `C# support`.
4. Распаковать архив в постоянную папку, например `C:\Tools\Godot\4.7.2`, и запустить исполняемый файл Godot из архива. Godot не требует отдельной установки.
5. Для редактирования C# использовать текущую IDE, если в ней удобно работать с проектом .NET. Дополнительный редактор на этом этапе не обязателен.

Готовность этапа: Godot открывается, а `dotnet --list-sdks` показывает установленный SDK 10.

## 2. Создать настоящий проект

**Выполнено:** проект создан в [`game/`](game/README.md). Сборка C# завершилась без ошибок и предупреждений; главная сцена запустилась через Godot и вывела диагностическое сообщение. Открыть проект можно через файл [`game/project.godot`](game/project.godot).

1. Создать проект Godot .NET в папке `game/` репозитория.
2. Зафиксировать версию SDK и структуру исходников, добавить правила игнорирования временных файлов Godot и сборки .NET.
3. Создать главную сцену и проверить её запуск из редактора.

Готовность этапа: открывается пустое окно игры без ошибок сборки.

## 3. Собрать каркас первого экрана

**Исследовательский проход выполнен:** в Godot собраны поверхность и один подземный этаж по эскизу, подключена панорама, работают камера, масштаб, сетка и выбор объектов. Добавлены видимая глубина пола, боковые грани помещений и толщина перекрытий. Этот экран ещё не утверждён как стиль и не содержит симуляции; его художественную переработку отложили до проверки игрового цикла.

1. Камера с перемещением и масштабом; координаты мира соответствуют сетке: клетка 0,8 м, 100 клеток по ширине, 12 на этаж и разделитель 2 клетки.
2. Три уровня изображения: дальняя панорама, поверхность, разрез подземного этажа. Панорама движется медленнее ближнего плана.
3. Разместить по утверждённому эскизу флаг, ёж, КПП, ремонтируемые руины, вход слева, входную группу, лифт, лестницу, подземный коридор, завал и дверь маленькой комнаты.
4. Сначала использовать простые временные формы с правильным масштабом и силуэтами. После проверки композиции заменить их единым набором игровых изображений.

Готовность этапа: экран читается без подписей; дверь, лифт, лестница и завал различимы с обычного игрового масштаба.

## 4. Сделать серый игровой прототип восстановления

1. Выбор объектов и понятная карточка действия.
2. Взлом входа: таймер и возможность ускорить его мини-игрой.
3. Спуск в подземный коридор, расчистка завала, открытие первой комнаты.
4. Ресурсы, задачи, время и сохранение состояния после перезапуска.

Готовность этапа: игрок проходит последовательность без ручной правки данных, понимает причины успеха и простоя, пробует другой выбор и продолжает с сохранённого места.

Готовая игра начинается раньше: с управляемого большого убежища, экспедиции героя и нападения. Этот открывающий эпизод добавляется после систем жителей, экспедиций и боя по [этапу 7а плана](План реализации.md); текущий экран показывает бункер уже после катастрофы.

## 5. После проверки цикла собрать вертикальный срез

1. Утвердить один пример поверхности и одного подземного этажа в фирменном упрощённом стиле.
2. Сделать согласованные тайлы, двери, силуэты персонажей, свет, тени и читаемый интерфейс.
3. Добавить смену времени суток и первые звуки окружения.
4. Проверить кадры при обычном масштабе, приближении и отдалении; исправить нечитаемые объекты и пустые зоны.

Готовность этапа: один законченный вертикальный фрагмент игры выглядит цельно и поддерживает действия пролога. Только после этого расширяем этажи и список комнат.
