# Технологический стек «Живого бункера»

**Статус: рабочее решение для прототипа, 5 октября 2026 года.** Первый выпуск — одиночная игра для Windows PC через VK Play, затем выпуск в Steam. Linux проверяется и выпускается отдельно. Браузерный выпуск и постоянный общий сервер не входят в первые выпуски. Версии фиксируются в проектных файлах после технического прототипа. Порядок магазинов описан в [плане публикации](Публикация.md).

Визуальные ресурсы и музыка создаются по [арт- и аудионаправлению](Визуальный стиль и музыка.md).

## Как это собирается в продукт

```text
Godot-клиент ── команды/обновления ── ASP.NET Core сервер
      │                                    │
      │                             C# симуляция мира
      │                                    │
 локальная C# симуляция               PostgreSQL
      │
   SQLite-сохранение

          JSON-контент → клиент и симуляция
```

В одиночном режиме Godot запускает библиотеку симуляции локально. Клиент передаёт ей те же команды, что отправил бы серверу, и получает те же результаты. Это позволяет играть без поднятия отдельного сетевого процесса и проверять большую часть правил на одном коде. В сетевом режиме библиотекой владеет ASP.NET Core сервер, а клиент лишь показывает подтверждённое состояние.

`contracts/` содержит версии команд и обновлений для сетевого режима; локальный режим использует те же смысловые операции без обязательной упаковки каждого вызова в сетевой пакет. Сохранение реализуется через отдельные адаптеры для SQLite и PostgreSQL. Правила игры не знают, какой адаптер подключён.

## Почему такой выбор

- **Godot + C#** соответствует 2.5D-виду бункера и даёт единый язык с сервером. Официальная документация подтверждает поддержку C# на настольных платформах. При этом проекты Godot 4 на C# сейчас не экспортируются в веб; если браузер становится обязательной платформой, выбор клиента нужно пересмотреть до начала большого объёма контента. [Godot C#](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/c_sharp_basics.html)
- **Отдельная библиотека симуляции** позволяет не связывать сотни и тысячи жителей с деревом сцен Godot и кадрами отрисовки. Это проектное решение, которое проверяется нагрузочным прототипом.
- **WebSocket** достаточен как первая гипотеза для строительства, политики, событий и автоматического боя с короткими реакциями. Официальная документация Godot прямо указывает, что транспорт надёжен, но не рассчитан на наиболее чувствительные к задержке приложения; потому сетевой боевой прототип обязателен до окончательной фиксации транспорта. [Godot WebSocket](https://docs.godotengine.org/en/stable/tutorials/networking/websocket.html)
- **Две базы хранения** соответствуют двум режимам: локальный файл для одиночной игры и центральная БД для общего мира. Разница скрыта за интерфейсом сохранения; данные мира имеют одну версионируемую модель.

## Что используем в первом вертикальном срезе

1. Godot .NET клиент для действующего двухуровневого бункера, карточек, мастерской, маршрута последней экспедиции и двух приближённых экранов автоматического боя.
2. C# библиотека симуляции для времени, задач Светы, расписания, производства, стройки, предметов, экипировки, экспедиции, боя и перехода к руинам по [контракту демо](Этапы/03-SYSTEMS/Контракты%20систем%20демо-пролога.md).
3. JSON-контент для готовых комнат, проекта мастерской, оружия, куртки, учебных задач, маршрута, реакций и проверочного баланса.
4. Русский и английский каталоги текстов, выбор языка в настройках и проверка отсутствующих ключей.
5. SQLite-сохранение текущего учебного шага, незавершённых работ, ресурсов, похода, боя и состояния героя.
6. Проверки ключевых правил расхода, сохранения и полной цепочки пролога, особенно повторной команды и загрузки во время боя.

ASP.NET Core, WebSocket и PostgreSQL подключаются в сетевом прототипе **после одиночных выпусков в VK Play и Steam**. Границы модулей и команды проектируются с учётом будущего сервера уже на первом этапе.

## Проверки перед окончательным утверждением

| Прототип | Что должно подтвердиться |
| --- | --- |
| Разрез бункера | Godot удобно показывает много этажей, предметы, рабочих и проект перепланировки; изображение остаётся читаемым |
| Большое поселение | Симуляция задач, маршрутов и потребностей укладывается в выбранный бюджет игрового шага на целевой машине |
| Сохранение | Мир загружается посреди стройки и вылазки без потерь или дублирования ресурсов |
| Два клиента — после одиночных выпусков | Сервер сохраняет единое состояние при одновременных командах, задержках и повторной отправке |
| Сетевой бой — после одиночных выпусков | Выбранный транспорт даёт приемлемую отзывчивость для тактических приказов и вмешательства героя |

Если один из прототипов не проходит проверку, меняем конкретный компонент или ограничение продукта и обновляем это решение до расширения контента.

## Что пока не добавляем в стек

Отдельные микросервисы, брокер сообщений, Redis, распределённые регионы, Kubernetes и собственный игровой движок пока не решают проверенную проблему проекта. Их можно добавить после измерений сетевого прототипа или большого поселения. Решение о конкретной библиотеке ORM, бинарном сетевом формате и системе телеметрии также принимаем при реализации соответствующего этапа.
